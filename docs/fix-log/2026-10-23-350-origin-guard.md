# 2026-10-23 22:07 — #350 No Origin / Sec-Fetch-Site check on cookie-authenticated /api writes
## Prompt
"do #350"
## Root cause
The only CSRF defence was SameSite=Lax on the session cookie. Nothing on the server looked at `Origin` / `Sec-Fetch-Site`, so a cross-site `POST /api/auth/logout` (and any other write) was accepted whenever the browser attached the cookie.
## Fix
New `server/middleware/origin-guard.js`, mounted `app.use('/api', originGuard)` before all `/api` routers. Non-GET/HEAD/OPTIONS: with `Origin`, host must equal the request Host (tunnel forwards the public Host) or be in `CORS_ORIGIN`; without `Origin`, `Sec-Fetch-Site` must be absent / same-origin / none. Else 403 `CROSS_SITE_BLOCKED`. i18n keys vi+en; `?v=` re-hashed. GET (OAuth callback) untouched; no token-based CSRF. Branch fix/350-origin-check off dev.
## Verification
`server/tests/origin-guard.test.js` (cross-site POST/PUT/PATCH/DELETE 403, Sec-Fetch-Site, same-origin, header-less, GET, CORS_ORIGIN list, mount order). `npm test` 197 suites / 3533 pass; cache-bust OK. Live on an isolated server (temp DB): cross-site guest + logout 403 and session survives; same-origin 200; tunnel-style Host+Origin 204. NOT verified: real browser login/logout, real Cloudflare tunnel, other write routes individually (guard is global).
