# Fix log entry — 2026-08-03 00:26

## Prompt

User request: finish the "further" delta step for `room:updated` that TODO.md #8 deliberately deferred as optional — `room:updated` still sent the full `users[]` array (and `scoreTable`) to every member of a room on every sit/stand/ready/join/leave/kick/game-end, so total bytes still scaled O(n²) with room size (issue report.md §4.2's original complaint, only partially addressed by dropping `settings`).

## Action

Added `broadcastRoomUpdate(io, room[, opts])` to [server/socket/state.js](server/socket/state.js), same diff-at-broadcast-time technique `broadcastLobbyUpdate`/`lobby:patch` already uses: `users[]` is diffed per-user into `{ upserts, removed }` (a user only appears in `upserts` if its own serialized fields actually changed — a host handover naturally shows up as both the old and new host's entries changing, no special-casing needed) and `scoreTable` is included only when it changed; the small scalar fields (roomName/hostId/hostName/state/readyDeadline) are always included since they're O(1) regardless of room size. All **17/17** `room:updated` emit sites (LobbyHandler, RoomHandler ×7, GameHandler ×5, DisconnectHandler ×3, state.js's own `handleReadyWindowTimeout`) now call `broadcastRoomUpdate` instead of emitting directly; the one settings-change site passes `{ settings: true }`. Added `clearRoomUpdateSnapshot(roomId)`, called from `SocketHandler.js`'s `room_destroyed` listener (the single choke point for every room-teardown path), so the per-room diff-baseline Maps don't grow forever. [client/js/room-socket.js](client/js/room-socket.js)'s `room:updated` handler now merges the `users` patch into its local list by `userId` (a `Map`, same technique `lobby.js` uses for `lobby:patch`) instead of the old shallow `Object.assign` (which worked when `users` was always a full array, but would silently accumulate stale entries or drop live ones once `users` became a patch). Bumped `?v=36` → `?v=37`.

## Decision

Reused the exact mechanism already proven for `lobby:patch` rather than inventing a new shape, on the theory that a second independent implementation of the same idea is a second place to get it subtly wrong. Kept `broadcastRoomUpdate` **synchronous** (no debounce, unlike `broadcastLobbyUpdate`/`broadcastOnlineUsers`) — this fix targets the O(n²) *payload* cost, not call frequency, and the room's own membership size (≤20) makes call-frequency a non-issue at this scale unlike the lobby-wide broadcasts fixed under TODO.md #9/#29. Switched the one `socket.to(...)` (join-notifies-others, excluding the joiner) call site in `LobbyHandler.js` to the shared `io.to(...)`-based helper for consistency — the joiner now also receives a redundant tiny delta of their own join right after their full `room:joined` payload; accepted as harmless (idempotent merge) rather than special-casing the helper for one caller.
