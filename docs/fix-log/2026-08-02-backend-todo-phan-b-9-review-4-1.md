## Prompt

Backend TODO Phần B #9 (review 4.1 + verification report on `3da53dd`): `broadcastLobbyUpdate` re-sent the **entire** room list to every lobby viewer on any change in any room — measured at 2670B for 10 rooms. Fix #12's 300ms debounce did not solve it: the verification pass showed real player pace (~1200ms between actions) puts each action in its own window, so the same 4 packets / 10759B went out as before. `instruction.md` §B9 is explicit that the debounce was only ever an interim step and that this item is not "done" while it stands alone; the reviewer's options were to raise the window to 1-2s as a cheap patch, or finish the delta, "after which the window size stops mattering". Took the delta.

## Action

`broadcastLobbyUpdate` now diffs the live room list against a per-io record of what the lobby was last sent, and emits `lobby:patch { upserts, removed }` — only changed rooms, and bare ids for destroyed ones. New `sendLobbySnapshot(io, socket)` sends the full list on `lobby:subscribe` (and seeds the baseline), so a client joining mid-stream has something to patch against. Client [lobby.js](client/js/lobby.js#L81-L106) keeps a `Map` keyed by roomId: `lobby:update` replaces it, `lobby:patch` applies removals then upserts. Bumped `?v=29` → `?v=30`.

## Decision

The diff is computed **at flush time from real state**, not described by callers — so none of the ~15 `broadcastLobbyUpdate` call sites changed, and none of them can describe a change wrongly or forget to. Removals are applied before upserts client-side so a room destroyed and recreated with the same id inside one window ends up present. Both operations are idempotent, which matters because a socket subscribing between two flushes gets a snapshot that may already contain a change the next patch also carries. A `Map` (not an array) keeps an updated room in place instead of moving it to the end of the lobby list. Also: a broadcast with no actual change now emits **nothing**, where before every call sent a full list. **Found while browser-verifying — an 18th lobby broadcast site the review's list of 15 did not include:** [SocketHandler.js:44](server/socket/SocketHandler.js#L44)'s `room_destroyed` handler emitted `lobby:update` with a full list straight to the lobby, bypassing `broadcastLobbyUpdate` entirely. It showed up as an unexplained 586B full-list frame in the middle of an otherwise all-delta capture, and because it never updated the baseline, the following patch re-announced the same removal. Routed through `broadcastLobbyUpdate` like every other site.
