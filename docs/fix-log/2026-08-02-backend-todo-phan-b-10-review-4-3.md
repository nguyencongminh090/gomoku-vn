## Action

`TimerManager.getSync()` returns `{black, white, activeColor, deadline, serverTime, running}`. The socket layer emits `timer:sync` only at discontinuities: game start, Swap2 resolution, bonus time (both auto-grant and accepted request), pause on disconnect, resume, and rejoin payloads (`room:joined`, `game:init`). Client [room-socket.js](client/js/room-socket.js#L205-L281) runs its own 1s countdown from the deadline, stopping at zero (the server sends `game:ended`) and on pause. Bumped `?v=30` → `?v=31`.

## Decision

Included `serverTime` despite it being outside the reviewer's ask, and noted why in the code: the client works in an offset (`serverTime - Date.now()` captured at each sync) and never compares its own wall clock to an absolute server timestamp, so a device with a badly wrong clock still counts correctly. It costs one number per message, sent a handful of times per game. `TODO.md` predicted `TimerManager.test.js`'s "start/tick" describe would need **rewriting**; it did not, and this is a deliberate deviation from that prediction — `onTick` is unchanged in behaviour and still fires every second, it simply is not wired to a socket any more, so those tests still assert something true and were kept as-is and extended. The pause path needed a sync emit that did not exist before: with no per-second traffic, a paused clock would otherwise be indistinguishable from silence and clients would keep counting down against a stopped server clock.
