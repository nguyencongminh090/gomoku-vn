## Root cause
All failures were stale e2e expectations after shipped features (#365, #367, #368, #369) plus one context-leak bug in `e2e/board-keyboard.spec.ts` (zero product regressions):
1. `#365` added `?from=rooms&id=…` when creating from `#rooms`; 20 files waited on `/room\.html\?id=/`.
2. `#369` desktop stage hid `.tab-btn[data-tab="tab-users"]` (spectators moved to `#aud-stack` → `#aud-pop`) and dissolved `.rail` via `display: contents` (breaking `getBoundingClientRect()` on `.rail`).
3. `#368` phone stage removed `#rpanel-toggle` in favour of `#btn-sheet` (`.rsheet` bottom sheet).
4. `#367` quiet banner (`BANNER_DELAY_MS = 8000`) delays showing `#status-banner` until Socket.io's Manager has already fired `reconnect_attempt`, so the banner opens directly on `Kết nối lại... (lần N)` instead of `Mất kết nối…` (not a `#435` regression).
5. `board-keyboard.spec.ts` never closed `A.ctx`/`B.ctx`, leaving a live room in the shared worker browser so `leave-then-create-room.spec.ts`'s `waitForEmptyLobby()` timed out; failed specs also leaked rooms until empty-room grace expired (`security-boundary` hit `MAX_ROOMS_PER_IP = 3`).

- `e2e/board-keyboard.spec.ts`: closed `A.ctx`/`B.ctx` in `try/finally`.
