Backend TODO Phần B #8 (review 4.2): `room:updated` re-sent the full room snapshot — `users[]` + `settings` + `scoreTable` — to every member of the room on sit/stand/ready/join/leave/kick/game-end, none of which change settings. Because one payload goes to each member, the waste scales with room size squared; the review measured 163B of a 2073B payload at 16 users and notes `MAX_USERS_PER_ROOM` is 20. `instruction.md` §B8 warns to reconcile against the **full list of 17 emit sites** from `issue report.md` §4.1/4.2 rather than whatever a grep happens to surface, and marks the further "delta per user action" step as explicitly optional.

## Action

Added `RoomManager.serializeRoomUpdate(room)` — `serializeRoom` minus `settings` — and switched all 17 `room:updated` emits to it, except the one in the `room:settings` handler ([RoomHandler.js:133](server/socket/handlers/RoomHandler.js#L133)), which is the only event where settings actually changed. Client side, [room-socket.js:59-72](client/js/room-socket.js#L59-L72) now merges (`Object.assign({}, st.roomData, data)`) instead of replacing, so settings from `room:joined` survive an update that omits them. ## Decision

Took only the "quickest win" the reviewer scoped; did **not** attempt the optional per-user delta. Verified the count against the source rather than trusting the grep: exactly 17 emit sites, matching the review. The client change was mandatory, not cosmetic — [room-ui.js:315](client/js/room-ui.js#L315) (`const s = st.roomData.settings`) and [game-ui.js:62](client/js/game-ui.js#L62) (`st.roomData.settings.boardSize`) both read settings **without** optional chaining, exactly the risk `TODO.md` flagged, so a replace-style assignment would have thrown on the first update. Left both call sites alone: merging keeps them correct, and adding optional chaining would paper over a real missing-data bug if one ever appeared. Two existing suites (`LobbyHandler.test.js`, `DisconnectHandler.test.js`) mock RoomManager and needed `serializeRoomUpdate` added to their mocks — their `serializeRoom` mocks now return a `settings` key too, so the mock shape matches the real split.
