# 2026-11-14 — #379 server/db helpers prepared SQL on every call
## Prompt
"Do #379" (B379: `prepare` top self-time frame in the play-lag CPU profile; also confirm prod MAX_ROOMS).
## Root cause
Every helper in `server/db/{users,profiles,games,rankings,tournaments,user-search}.js` called
`db.prepare(sql)` per invocation; preparing (SQL parse + plan) costs ~5x the query itself.
## Fix
- `connection.js` exports `stmt(sql)`: Map keyed by SQL text, one statement per text, cap 500
  (past it: prepared, not kept). Comment lists the limits (no .pluck/.raw/.expand, no iterate).
- All helpers use `stmt()` except the 4 rankings queries with a per-call `IN (?,?,…)` list
  (getRankingsAmong, countRankingsAmong, getRatingDeltas7, getPrimaryClubs) — text varies by N.
- Interpolated texts that stay: PROFILE_COLS constant, updateProfile SET combos, buildGameFilters WHERE —
  all bounded sets. Locals named `stmt` in createUser/tournaments renamed `insert`.
## Verification
- `server/tests/db-stmt-cache.test.js` (5 tests): same object per text, no `db.prepare` on repeat
  REST/auth helper calls, fresh data read, cap behaviour. Full `npm test`: 221 suites, 3885 tests green.
- Micro-bench (temp DB, 100k calls): `getUserById` 19.4 → 3.9 µs per call.
- Not re-profiled under the tools/perf load harness.
