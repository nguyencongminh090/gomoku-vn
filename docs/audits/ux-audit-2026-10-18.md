# UX audit — Rooms (desktop), 2026-10-18

**Verdict: Incomplete (scoped).** Scope was the room screen on branch `ui/room-rail-dock` (docked rail, dropdown settings, sorted score table, square board). Manifest covers 2 guest sessions, 1440 + resize sweep, settings, chat, collapse, one live game start. **Not run:** full 11-scenario battery, role/spectator, keyboard-only thread, heavy data, mobile interaction beyond a 375 screenshot, a real move sequence (my board click did not register — script, not verified as app bug), draw-offer receipt while collapsed.

Persona: casual Vietnamese player on a laptop, mid-game, glancing at the clock. Server: isolated `:3101`, temp DB (`GOMOKU_DB_PATH`), real DB untouched.

**Hard gates:** console errors 0, warnings 0 (app); network 4xx/5xx 0; axe Critical 0 / Serious 0 (only `page-has-heading-one`, moderate, pre-existing, 3 states); layout collapse 0 (no horizontal overflow 375–1920); CLS 0, LCP 88 ms (local, unthrottled). Tab order: 0 stops inside the hidden rail.

## Findings
**H1 — Collapsing the rail mid-game hides the clocks, game controls and request toasts.** Surface `/room.html` ≥769px, game ongoing, rail collapsed. Repro: seat 2 guests, both Bắt đầu, click `#rail-dock-toggle`. Observed: `.seatcard__clock` (both), `#game-controls`, `#game-toasts` all `visibility:hidden` (x>1440). Expected: a player can't lose sight of the clock or miss a draw/undo/time request because of a layout toggle. Evidence: `docs/audits/2026-10-18/10-game-collapsed-draw-offer.png`; request-toast loss inferred from DOM (`#game-toasts` lives in the rail), not exercised live. Location: `client/css/room-arena.css` `.rail-collapsed .rail`; `client/room.html` toasts inside `.rpanel`. Patch: when a game is ongoing and the rail is collapsed, keep seat cards + clocks visible (collapse only the tabs panel) or auto-expand the rail on an incoming request; at minimum show a pulsing dot on the tab when a request arrives.

**M1 — Tablet width squeezes the board.** 900×700 → board 501 px; 769 wide → ≈380 px with the 364 px rail open. Expected: board stays the focus. Location: `room-arena.css` `@media (min-width:769px)`. Patch: default-collapsed (or narrower `--rail-w`) between 769–1024px.

**L1 — Disabled "Tính điểm xếp hạng" row is misaligned.** Hint `<small>` wraps; its switch sits ~8 px right of the other switches (x 1368–1410 vs 1358–1402). Evidence `03-settings-dropdowns.png`. Location: `client/js/room-ui.js` `rankedBlocked` label. Patch: let the label shrink (`min-width:0; flex:1`) and keep the switch `flex:none`.

**L2 — Guest sees four identical "Cài đặt phòng đã được thay đổi." lines** for four different changes; none says what changed (first-time-user lens). Evidence: chat log in `manifest.txt`. Pre-existing; location server `RoomHandler` settings notice.

## Worked (proof)
Rail docked flush right (x=1076 w=364, board centred in the rest) · collapse/expand with persistence across reload · keyboard Enter/Space toggle · 4 dropdowns present and change the shared settings (guest received board 15 / caro / blitz / swap2) · board is square (`border-radius:0`) · chat send clears input, delivered to guest · 375px stacked layout unchanged.

**Hold this in your hands:** The docked panel finally reads as part of the room instead of a floating card, and the dropdowns tidy a settings tab that used to be a wall of pills. But the collapse is a spectator's affordance applied to a player's screen — hiding the clock is the one thing a player in a timed game can't afford, so it needs one more rule before it feels trustworthy.
